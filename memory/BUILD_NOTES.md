# LastZHood build notes

## Production Python dependencies
- `backend/requirements.in`: direct application imports (game, wallet, database, Early).
- `backend/requirements.txt`: fully pinned transitive production lock, generated by pip.
- Refresh safely with `bash scripts/lock_backend_dependencies.sh`; never freeze the entire shared development environment into this file.
- Test tools and local mock MongoDB are intentionally not part of the production image.
- The active `/root/.venv` has also been pruned to these same 46 packages, not just the lockfile: a previous cloud run pulled 147 packages despite a 46-package local lock. Keeping runtime and lock consistent prevents shared-environment freezing from reintroducing bloat. The exact platform sync behavior is not confirmed.
- Temporary verification-only tools are installed in `/tmp/lastzhood-tests`; run `/tmp/lastzhood-tests/bin/python -m pytest ...`. Do not install them into the production/backend environment or freeze them into the production lock.

## Browser runtime
- `frontend/runtime-assets/browser-wheels.zip` contains the ten required browser wheels. Some source snapshot pipelines filter individual `.whl` files; the explicitly allowed ZIP avoids relying on those files surviving export.
- `python scripts/package_local_engine.py` restores these wheels offline, generates game-only ZIP, and verifies required runtime files/checksums.
- `--runtime` is an explicit maintainer refresh, with network downloads; normal builds never use it.
- The archive stays outside `frontend/public`, so it is not duplicated into the public deployment.
- The implementation now lives in `frontend/scripts/package_local_engine.py`. CRACO invokes this frontend-local path, which survives Docker stages copying only `frontend/`; the repository-root script is a compatibility entry point.
- In a full checkout, game.zip is rebuilt deterministically from backend sources. In frontend-only builds, the shipped game.zip must pass its manifest hash and exact game-only member validation. Missing/corrupt bundles fail; nothing is downloaded or mocked.
- Explicit `--source-dir` and `--public-dir` arguments support split source/build locations without guessing `/workspace` or `/app` paths.

## Frontend build
- Production source maps are disabled by CRACO before CRA configuration is generated; development debugging remains unchanged.
- Do not remove Pyodide WASM or Python standard library: the game needs them.
- Actual cloud build/OOM diagnosis requires deployment logs. A successful local build does not prove a successful cloud deployment.
